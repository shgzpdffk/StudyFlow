# StudyFlow

Telegram Mini App для студентов: календарь дедлайнов и учет времени учебы по дисциплинам.

Проект в разработке. Ниже описан уже реализованный бэкенд.

## 1. Что уже работает

- Telegram-бот отвечает на `/start` и сохраняет пользователя в SQLite.
- Сервер проверяет авторизацию Telegram Mini App.
- Пользователь создает дисциплины и получает только свой список.
- Данные сохраняются после перезапуска.
- Структура базы обновляется через миграции Alembic.

Дедлайны реализованы на уровне API. Календарь, таймер, статистика и React-интерфейс пока не реализованы.

## 2. Компоненты

| Компонент | Назначение |
|---|---|
| FastAPI | Принимает HTTP-запросы и возвращает ответы |
| Pydantic | Проверяет данные запросов и описывает ответы |
| SQLAlchemy | Читает и сохраняет данные в базе |
| SQLite | Хранит пользователей и дисциплины в файле |
| Alembic | Создает и изменяет структуру таблиц |
| aiogram | Получает сообщения Telegram и отправляет ответы |
| pydantic-settings | Загружает настройки из `.env` |

Сервер и бот запускаются отдельными процессами, но используют одну базу.

## 3. Основные сценарии

### Команда /start

1. Telegram передает сообщение запущенному боту.
2. Бот получает Telegram ID и имя отправителя.
3. Приложение находит пользователя в базе или создает его.
4. Бот отправляет приветствие.

Повторный `/start` не создает дубликат пользователя. Если настроен `WEBAPP_URL`,
в ответе появляется кнопка Mini App. Пока адрес пустой, бот работает без кнопки.
Команда регистрации предназначена для личного чата с ботом.

### Авторизация API

Будущий фронтенд получает `Telegram.WebApp.initData` и передает заголовок:

```text
Authorization: tma <initData>
```

Сервер проверяет наличие заголовка, подпись данных и время выдачи.
По умолчанию данные действуют один час. Затем сервер получает Telegram ID
из проверенных данных, находит или создает пользователя и выполняет запрос от его имени.

`initData` — данные запуска Mini App, а не токен бота. Токен хранится только на сервере.
После истечения срока авторизации необходимо заново открыть Mini App.

### Создание дисциплины

1. Клиент отправляет название в `POST /subjects`.
2. Сервер проверяет авторизацию и входные данные.
3. Назначает текущего пользователя владельцем.
4. SQLAlchemy сохраняет дисциплину в SQLite.
5. Сервер возвращает ID и название.

Клиент не выбирает владельца: `user_id` назначает сервер.

### Получение дисциплин

После проверки авторизации сервер выбирает только дисциплины текущего пользователя
и возвращает список, отсортированный по ID.

## 4. База данных

### users

| Поле | Значение |
|---|---|
| `id` | Внутренний ID пользователя |
| `telegram_id` | Уникальный ID аккаунта Telegram |
| `name` | Имя пользователя |

### subjects

| Поле | Значение |
|---|---|
| `id` | ID дисциплины |
| `name` | Название |
| `user_id` | Ссылка на владельца в `users` |

Один пользователь может иметь несколько дисциплин.
Старые общие записи из учебной версии сохраняются с `user_id=NULL` и не выдаются
пользователям, поскольку их владелец неизвестен. Новые записи всегда получают владельца.

## 5. API

| Метод | Адрес | Назначение | Авторизация |
|---|---|---|---|
| GET | `/health` | Проверка работы сервера | Нет |
| GET | `/me` | Свой профиль | Да |
| GET | `/subjects` | Свои дисциплины | Да |
| POST | `/subjects` | Создать дисциплину | Да |

### Проверка сервера

`GET /health` возвращает:

```json
{"status": "ok"}
```

Этот запрос проверяет доступность приложения, но не выполняет отдельную проверку базы.

### Создание дисциплины

Тело `POST /subjects`:

```json
{"name": "Математика"}
```

Пример ответа со статусом `201`:

```json
{"id": 1, "name": "Математика"}
```

Название должно быть строкой длиной от 1 до 80 символов. Пробелы по краям удаляются;
пустое название и название из одних пробелов запрещены. Одинаковые названия разрешены.

### Получение списка

Пример ответа `GET /subjects`:

```json
[
  {"id": 1, "name": "Математика"},
  {"id": 2, "name": "Физика"}
]
```

Если дисциплин нет, возвращается `[]`.

### Профиль

Пример ответа `GET /me`:

```json
{"id": 1, "telegram_id": 123456789, "name": "Студент"}
```

### Ошибки

| Код | Причина |
|---|---|
| `401` | Авторизация отсутствует, повреждена или просрочена |
| `422` | Некорректные данные запроса |
| `503` | Не настроен токен для проверки авторизации Telegram |

## 7. Настройки и секреты

Python 3.10 или новее. В `backend/.env`:

```dotenv
BOT_TOKEN=токен_от_BotFather
WEBAPP_URL=
INIT_DATA_MAX_AGE=3600
```

- `BOT_TOKEN` нужен боту и проверке авторизации.
- `WEBAPP_URL` — публичный HTTPS-адрес фронтенда. Пока можно оставить пустым.
- `INIT_DATA_MAX_AGE` — срок действия авторизации в секундах.

Если `.env` еще нет, создайте его по образцу `.env.example`.
Не перезаписывайте существующий файл с токеном.
`.env`, окружение и база исключены из Git. Пустой `.env.example` можно публиковать.
Токен нельзя вставлять в Python-код, фронтенд или README.

## 8. Запуск

Все команды ниже выполняются из корня репозитория, затем из `backend`.
При первом запуске создайте окружение, если его еще нет:

```bash
cd backend
python3 -m venv .venv
```

### Сервер

```bash
# Выполнять из backend
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m uvicorn app.main:app --reload
```

Документация: http://127.0.0.1:8000/docs

Зависимости переустанавливают при их изменении. Миграции применяют перед запуском
обновленной версии. Перед миграцией существующей базы остановите приложение и сделайте копию базы.

### Бот — отдельный терминал

Сначала заполните `BOT_TOKEN` в `.env`.

```bash
# Из корня репозитория
cd backend
source .venv/bin/activate
python -m app.bot.main
```

Отправьте `/start` в личном чате с ботом.

### Будущие изменения структуры базы

После изменения моделей:

```bash
python -m alembic revision --autogenerate -m "describe schema change"
# Просмотрите сгенерированную миграцию перед применением.
python -m alembic upgrade head
```

## 9. Проверки

### Вручную

- `/health` возвращает `{"status": "ok"}`.
- Бот отвечает на `/start`, повторный вызов не создает дубликат пользователя.
- Защищенный API без авторизации возвращает `401`.

В `/docs` нажмите **Authorize** и передайте `tma <initData>` для защищенных запросов.
Токен бота в это поле вводить нельзя. Полноценную ручную проверку входа и создания
дисциплин через Telegram выполняем после подключения Mini App.

### Автоматически

```bash
# Из backend, с активным окружением
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
```

При реализации прошли 10 тестовых случаев. Они проверяют разделение данных,
неправильные названия, просроченную и поддельную авторизацию, отсутствие токена,
сохранение старых записей при миграции, обработчик `/start` и кнопку Mini App.
Используются временные базы и тестовый токен; обращения к настоящему Telegram нет.

## 10. Ограничения и следующий этап

Пока отсутствуют фронтенд, таймер, статистика, изменение и удаление дисциплин.
Размещение на хостинге и живое подключение бота требуют отдельной проверки.

Реализованный этап — дедлайны:

1. Таблица: ID, дисциплина, название задания, дата и время сдачи, статус выполнения.
2. Миграция Alembic для создания таблицы.
3. Схемы проверки входных данных и ответов.
4. API создания, списка, редактирования, удаления и отметки выполнения.
5. Проверка принадлежности дисциплины и дедлайна текущему пользователю.
6. Тесты основных действий и запрета доступа к чужим данным.

Готовность этапа: пользователь управляет своими дедлайнами через API, данные
сохраняются после перезапуска, чужие дедлайны недоступны. Сам календарь будет отображаться на фронтенде.


## API дедлайнов

Все запросы требуют авторизацию Telegram.

| Метод | Адрес | Назначение |
|---|---|---|
| POST | `/deadlines` | Создание |
| GET | `/deadlines` | Список своих дедлайнов |
| GET | `/deadlines/{id}` | Одна запись |
| PATCH | `/deadlines/{id}` | Изменение переданных полей |
| DELETE | `/deadlines/{id}` | Удаление; ответ 204 без тела |

Пример создания:

```json
{"subject_id": 1, "title": "Сдать работу", "due_at": "2026-11-10T18:00:00+03:00"}
```

Ответ содержит id, subject_id, title, due_at, done. Дисциплина должна принадлежать
текущему пользователю. Дата сохраняется и возвращается в UTC, например 15:00Z
для 18:00+03:00. Дата без часового пояса запрещена; прошедшие сроки разрешены.
Название — 1–200 символов; пробелы по краям удаляются.

Для отметки выполнения отправьте PATCH с `{"done": true}`, для отмены —
`{"done": false}`. Также можно менять title, due_at и subject_id.
Пустой PATCH, null и неизвестные поля отклоняются с 422.
Чужие и отсутствующие записи возвращают одинаковый статус 404.

Список сортируется по сроку и ID. Фильтры: subject_id, done.
Пагинация: limit (по умолчанию 100, максимум 200), offset (по умолчанию 0).
Пример: `/deadlines?done=false&limit=20&offset=0`.

Новые файлы: app/deadlines.py — маршруты; app/deadline_schemas.py — схемы;
migrations/versions/003_deadlines.py — миграция; tests/test_deadlines.py — тесты.
Таблица deadlines: id, subject_id, title, due_at, done. Владелец определяется через дисциплину.

Перед запуском новой версии из backend: `python -m alembic upgrade head`.
Следующий этап — учебные сессии и таймер.
