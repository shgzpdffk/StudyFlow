# StudyFlow — фронтенд, этап 1 из 4

React + TypeScript + Vite. Интерфейс на русском языке, с адаптацией под телефон и компьютер.

## Что уже работает

- Стартовый экран и экран дисциплин.
- Получение профиля через `GET /me` и предметов через `GET /subjects`.
- Добавление дисциплины через `POST /subjects`: проверка названия, состояние сохранения, сообщение об успехе.
- Поиск по загруженным дисциплинам.
- Пустой список, загрузка, ошибки, повторная попытка и истекшая авторизация.
- Демо в обычном браузере: примерные предметы без запросов к API. Изменения живут в памяти страницы и исчезают после перезагрузки или выхода из демо.

Календарь, таймер и статистика пока обозначены как «Скоро». Редактирования и удаления дисциплин на этом этапе нет.

## Запуск

Нужны Node.js 22.12+ и pnpm 11. Для установки pnpm при установленном Node.js:

```sh
npm install -g pnpm@11
```

Из корня проекта в первом терминале запусти сервер:

```sh
cd backend
source .venv/bin/activate
python -m alembic upgrade head
python -m uvicorn app.main:app --reload
```

Во втором терминале, также из корня проекта:

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Открой <http://127.0.0.1:5173>. Кнопка «Посмотреть демо» работает даже без запущенного Python-сервера.

Браузер вне Telegram не получает данные настоящего пользователя. Для реальных предметов приложение нужно открыть как Mini App через бота. Локальный HTTP-адрес предназначен для разработки: для запуска через Telegram нужен публичный HTTPS-адрес, указанный в серверной настройке `WEBAPP_URL`. Его размещение — отдельный этап.

## Как связаны интерфейс и сервер

```text
React → /api/subjects → прокси Vite → FastAPI /subjects → SQLite
```

В разработке Vite пересылает `/api/*` на `http://127.0.0.1:8000`, удаляя `/api`. Если сервер работает на другом порту:

```sh
API_PROXY_TARGET=http://127.0.0.1:8001 pnpm dev
```

При открытии в Telegram интерфейс получает `Telegram.WebApp.initData` и передает его в заголовке `Authorization: tma <initData>`. Подпись и владельца данных определяет существующий бэкенд. Фронтенд не передает `user_id` при создании предмета и не хранит `initData` в localStorage.

Токен бота остается только в `backend/.env`. Он не нужен React и не должен попадать в переменные `VITE_*`: такие переменные доступны посетителям сайта.

## Где что находится

| Файл | Назначение |
|---|---|
| `src/main.tsx` | Подключение React к HTML-странице |
| `src/App.tsx` | Основной экран, состояние списка, поиск и сообщения |
| `src/SubjectDialog.tsx` | Форма добавления предмета и ее проверки |
| `src/api.ts` | HTTP-запросы, ошибки API и отдельный источник демоданных |
| `src/telegram.ts` | Инициализация Telegram Mini App |
| `src/styles.css` | Оформление и адаптация к ширине экрана |
| `vite.config.ts` | Настройка сборщика и локального прокси |
| `tests/subjects.spec.ts` | Проверки сценариев в браузере |
| `pnpm-lock.yaml` | Зафиксированные версии зависимостей |
| `pnpm-workspace.yaml` | Разрешение установочного скрипта сборщика esbuild |

TypeScript добавляет к JavaScript проверки типов: например, предмет должен содержать числовой `id` и строковый `name`. В браузер при сборке попадает JavaScript. Python-сервер остается отдельным приложением.

## Проверки и сборка

Из папки `frontend`:

```sh
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

Сборка проверяет типы и создает `dist/`. Браузерные тесты проверяют сценарии на ширине компьютера и телефона в Chromium: демо, загрузку, поиск, добавление, пустое название, перезагрузку, пустой список, закрытие формы клавишей Escape, ошибки сервера и истекшую сессию. Ответы API и Telegram SDK в этих тестах подменяются; это не проверка входа в настоящем Telegram и не эмуляция Safari.

`pnpm preview` позволяет посмотреть собранный сайт локально. Для публикации нужно отдельно настроить HTTPS, раздачу `dist/` и проксирование `/api/*` к FastAPI с удалением `/api`. Прокси из `vite.config.ts` не входит в статические файлы сборки. Развертывание в этой версии не выполнено.

## Следующие этапы

1. **Готово:** каркас приложения, адаптивный экран дисциплин, авторизация для запросов и добавление предметов.
2. **Календарь:** отображение дедлайнов по датам, создание, изменение, завершение и удаление через готовый API.
3. **Фокус:** запуск и остановка таймера, восстановление активного занятия после открытия, история занятий.
4. **Статистика и выпуск:** время по дисциплинам и дням, часовой пояс устройства, проверка полного сценария в Telegram, HTTPS-размещение и финальная доработка.

Это четыре функциональных этапа, а не обещание одинаковой трудоемкости каждого.
