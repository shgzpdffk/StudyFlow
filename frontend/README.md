# StudyFlow — фронтенд, этап 3 из 4

React + TypeScript + Vite. Интерфейс на русском языке, с адаптацией под телефон и компьютер.

## Что уже работает

- Стартовый экран и экран дисциплин.
- Получение профиля через `GET /me` и предметов через `GET /subjects`.
- Добавление дисциплины через `POST /subjects`: проверка названия, состояние сохранения, сообщение об успехе.
- Поиск по загруженным дисциплинам.
- Календарь месяца с выбором дня, переключением месяцев и возвратом к сегодняшнему дню.
- Добавление и редактирование задания: название, дисциплина, дата и время.
- Выполнение и возврат задания в работу; удаление с подтверждением.
- Фильтры календаря и списка по дисциплине и статусу, отметки просроченных заданий.
- Раздел «Фокус»: выбор дисциплины, запуск и завершение одного активного занятия.
- Восстановление активного занятия с сервера при открытии раздела, в том числе после перезагрузки страницы.
- История завершенных занятий с длительностью, местными датами начала и окончания, фильтром по дисциплине и загрузкой по 20 записей.
- Переключение между дисциплинами, календарем и таймером на компьютере и телефоне.
- Пустой список, загрузка, ошибки, повторная попытка и истекшая авторизация.
- Демо в обычном браузере: примерные предметы без запросов к API. Изменения живут в памяти страницы и исчезают после перезагрузки или выхода из демо.

Статистика пока обозначена как «Скоро». Редактирования и удаления дисциплин на этом этапе нет.

## Запуск

Нужны Node.js 22.12+ и pnpm 11. Для установки pnpm при установленном Node.js:

```sh
npm install -g pnpm@11
```

Из корня проекта в первом терминале запусти сервер:

```sh
cd backend
source .venv/bin/activate
python -m alembic upgrade head
python -m uvicorn app.main:app --reload
```

Во втором терминале, также из корня проекта:

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Открой <http://127.0.0.1:5173>. Кнопка «Посмотреть демо» работает даже без запущенного Python-сервера.

Браузер вне Telegram не получает данные настоящего пользователя. Для реальных предметов приложение нужно открыть как Mini App через бота. Локальный HTTP-адрес предназначен для разработки: для запуска через Telegram нужен публичный HTTPS-адрес, указанный в серверной настройке `WEBAPP_URL`. Его размещение — отдельный этап.

## Как связаны интерфейс и сервер

```text
React → /api/subjects → прокси Vite → FastAPI /subjects → SQLite
```

В разработке Vite пересылает `/api/*` на `http://127.0.0.1:8000`, удаляя `/api`. Если сервер работает на другом порту:

```sh
API_PROXY_TARGET=http://127.0.0.1:8001 pnpm dev
```

При открытии в Telegram интерфейс получает `Telegram.WebApp.initData` и передает его в заголовке `Authorization: tma <initData>`. Подпись и владельца данных определяет существующий бэкенд. Фронтенд не передает `user_id` при создании предмета и не хранит `initData` в localStorage.

Токен бота остается только в `backend/.env`. Он не нужен React и не должен попадать в переменные `VITE_*`: такие переменные доступны посетителям сайта.

## Как работает календарь

При открытии раздела интерфейс получает дедлайны через `GET /deadlines?limit=200&offset=0`. Если пришло 200 записей, запрашивает следующую страницу с `offset=200`, затем 400 и так далее, пока не получит неполную страницу. Так задания после первой страницы не теряются. Переключение месяца и фильтры работают с загруженным списком без новых запросов.

API пока не умеет отбирать записи по диапазону дат, поэтому загружается весь список. Для большого объема данных следующим улучшением станет фильтр периода на сервере. Изменения из другого окна появляются после повторного открытия календаря или перезагрузки страницы; автоматической синхронизации пока нет.

| Действие | Запрос |
|---|---|
| Добавить задание | `POST /deadlines` с `subject_id`, `title`, `due_at` |
| Изменить задание | `PATCH /deadlines/{id}` с измененными данными |
| Завершить или вернуть в работу | `PATCH /deadlines/{id}` с `done: true/false` |
| Удалить после подтверждения | `DELETE /deadlines/{id}`, успешный ответ 204 без JSON |

Список меняется только после успешного ответа. При ошибке форма сохраняет введенный текст, а неуспешное завершение или удаление оставляет задание в списке. При 401 приложение скрывает данные и предлагает открыть Mini App заново. Создание дедлайна доступно после добавления хотя бы одной дисциплины.

**Дата и время:** поле формы использует местное время устройства. Например, 5 января в 00:30 в Москве отправляется как 4 января в 21:30 UTC, но в календаре остается на 5 января. Для группировки по дням используются местные компоненты даты, а не обрезанная UTC-строка. Часовой пояс показан рядом с фильтрами и в форме.

При переходе на летнее время несуществующий час отклоняется с объяснением. При повторяющемся часе осенью используется стандартный выбор браузера; выбор второго смещения в интерфейсе пока не предусмотрен. Если меняется только название или дисциплина, исходное время сохраняется точно, включая секунды. Прошедшие даты разрешены; невыполненные задания с прошедшим сроком помечаются как просроченные. Проверка этого статуса обновляется каждые 30 секунд.

Демо-календарь использует отдельный список в памяти: изменения переживают переход между разделами, но исчезают при перезагрузке или выходе из демо. Реальная база при этом не используется.

## Как работает таймер

Раздел «Фокус» использует готовый API учебных сессий. У пользователя может быть одно активное занятие. Новый запуск разрешается только после подтверждения сервером, что активного занятия нет, и при наличии дисциплины.

| Действие | Запрос |
|---|---|
| Проверить активное занятие | `GET /sessions/active`: объект или `null` |
| Начать | `POST /sessions/start` с единственным полем `subject_id` |
| Завершить конкретное занятие | `POST /sessions/{id}/stop` |
| Загрузить историю | `GET /sessions?completed=true&limit=20&offset=0` |
| История по предмету | Тот же запрос с `subject_id` |

Сервер определяет время начала и окончания. Фронтенд не отправляет собственные временные метки, длительность или владельца. Экран берет `duration_seconds` из ответа и прибавляет время, прошедшее по монотонным часам браузера (`performance.now()`). Интервал перерисовывает цифры, а не записывает каждую секунду в базу. Формат — часы:минуты:секунды; после 24 часов счетчик не обнуляется.

При открытии раздела, возвращении к окну приложения, восстановлении сети и каждые 30 секунд, пока раздел открыт и страница видна, состояние повторно запрашивается с сервера. Это восстанавливает таймер после перезагрузки и обнаруживает изменения с другого устройства. После перезагрузки открой «Фокус» снова — текущий раздел пока не сохраняется в адресе. В других разделах отсчет в базе продолжается, а запросы таймера не выполняются.

**Закрытие Mini App не завершает занятие.** Закончив учиться, нажми «Завершить занятие». Для запуска и остановки нужна сеть и действующая авторизация. Пауза, ручная правка длительности и удаление занятий пока не реализованы.

Пока запрос выполняется, повторные нажатия заблокированы. При конфликте 409 загружается уже активное занятие. После любой попытки записи, включая ошибку сети, состояние сверяется с сервером: ответ мог потеряться уже после сохранения. Автоматического повторения POST нет. Если сверка не удалась, действия блокируются до успешного обновления; прежний отсчет может оставаться на экране как приблизительный, с сообщением об ошибке. Остановка всегда обращается к ID показанного занятия и не должна останавливать новый таймер, запущенный на другом устройстве.

История загружается отдельно от активного таймера. Ошибка истории не мешает завершить занятие. Кнопка «Показать еще» получает следующую страницу, фильтр дисциплины выполняется сервером. После завершения история обновляется. Время занятия берется из ответа API, даты показываются в часовом поясе устройства; для занятий через полночь видны обе даты.

Демо использует отдельный список в памяти. Его таймер переживает переход между разделами, но сбрасывается после перезагрузки или выхода из демо и не сохраняет ничего в настоящую базу.

| Файл | Назначение |

| `src/main.tsx` | Подключение React к HTML-странице |

| `src/api.ts` | HTTP-запросы, ошибки API и отдельный источник демоданных |
| `src/telegram.ts` | Инициализация Telegram Mini App |
| `src/styles.css` | Оформление и адаптация к ширине экрана |
| `vite.config.ts` | Настройка сборщика и локального прокси |
| `tests/subjects.spec.ts` | Проверки дисциплин в браузере |
| `tests/focus.spec.ts` | Проверки таймера, восстановления, истории, сетевых ошибок и демо |
| `tests/calendar.spec.ts` | Проверки календаря, действий, дат, пагинации и ошибок |
| `pnpm-lock.yaml` | Зафиксированные версии зависимостей |
| `pnpm-workspace.yaml` | Разрешение установочного скрипта сборщика esbuild |

TypeScript добавляет к JavaScript проверки типов: например, предмет должен содержать числовой `id` и строковый `name`. В браузер при сборке попадает JavaScript. Python-сервер остается отдельным приложением.

## Проверки и сборка

Из папки `frontend`:

```sh
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

Сборка проверяет типы и создает `dist/`. Браузерные тесты проверяют сценарии на ширине компьютера и телефона в Chromium: демо, загрузку, поиск, добавление, пустое название, перезагрузку, пустой список, закрытие формы клавишей Escape, ошибки сервера и истекшую сессию. Для календаря дополнительно проверяются создание, перенос на другую дату, завершение и возврат в работу, удаление с подтверждением, фильтры, загрузка более 200 записей, граница суток, переход часов, ошибки 404 и повторное нажатие при сохранении. Для таймера проверяются запуск и остановка, восстановление после перезагрузки, отсчет по серверной длительности, история с пагинацией и фильтром, конфликт 409, потерянные ответы, блокировка неподтвержденного состояния, истечение авторизации и изоляция демо. Ответы API и Telegram SDK в этих тестах подменяются; это не проверка входа в настоящем Telegram и не эмуляция Safari.

`pnpm preview` позволяет посмотреть собранный сайт локально. Для публикации нужно отдельно настроить HTTPS, раздачу `dist/` и проксирование `/api/*` к FastAPI с удалением `/api`. Прокси из `vite.config.ts` не входит в статические файлы сборки. Развертывание в этой версии не выполнено.

Это четыре функциональных этапа, а не обещание одинаковой трудоемкости каждого.
